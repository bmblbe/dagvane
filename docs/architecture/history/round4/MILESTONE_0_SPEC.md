## 4. Вимоги транспортної правди (E-WIRE)

Постійний регресійний тест: стаб-клієнт фіксує **фактичні kwargs на межі SDK** для кожного dispatch. Покриття: `model` (default і `--model`), `max_tokens` (default і `--max-tokens`), `temperature` (config, `--temperature`, opus-виняток `:492`), `top_p`, `top_k`, `--no-sampling` (усі три відсутні), `system` (config і `--system`; порожній — відсутній), `extra_headers` із PDF-вкладенням, **кожен continuation-dispatch** (ті самі params/headers у раундах продовження), плюмбінг `timeout`/`max_retries` у конструктор клієнта. Обов'язково задокументований **fail-before-pass**: тест написаний до фіксу D1, червоний на поточному коді, зелений після.

## 5. Lazy import SDK / поведінка `--help`

Імпорт `anthropic` переноситься всередину команд, що його потребують (`chat`, `models` без `--local`). У чистому venv без SDK: `--help` (і всі `--help` підкоманд), `init`, `config view/path/reset/set`, `settings`, `sessions`, `history`, `answer`, `clear`, `models --local` — працюють. Команди, що потребують SDK, за його відсутності завершуються тим самим повідомленням, що й нині (`Missing dependency 'anthropic'. Run: pip install -r requirements.txt`), з ненульовим кодом.

## 6. Політика блокування/пошкодження JSONL

- **Блокування:** ексклюзивний `flock` на файл блокування сесії охоплює **одну транзакцію**: append user+assistant пари + `update_meta` (read-modify-write) — одним скоупом; `clear` бере той самий lock. Linux/POSIX-семантика (бутстрап-оркестрація Linux-only; для legacy CLI на не-POSIX — best-effort no-op з задокументованою межею).
- **Биті рядки:** політика фіксується як «пропустити рядок + одне stderr-попередження з лічильником на команду» (нинішній мовчазний пропуск `:448-453` — задокументований дефект); характеризаційний тест на файл із битим рядком і на torn tail (обірваний останній рядок). Строгі гарантії (gapless, відновлення) — властивість майбутнього RunStore, **не** ретрофіт `sessions/`.

## 7. Контейнмент вкладень

Оператор CLI — довірена межа в M0 (**тимчасовий compatibility baseline**; фінальна політика — власник, `ARCHITECTURE_DECISION.md` §15.2). Дії M0: у метадані запису додається **сирий user-supplied шлях** поряд із уже записуваним resolved (`raw_path` + наявний `path`); у код/доки — нотатка про межу довіри (оператор — довірений; будь-який model-driven шлях у майбутньому — тільки через ToolBroker із default-deny). Жодного default-deny для операторських прапорців у M0.

## 10. Безпека і секрети в межах обсягу

- Створення `secrets.env`: атомарно через `os.open(..., O_WRONLY|O_CREAT|O_EXCL, 0o600)` (не «створити широко, потім chmod»); наявний файл не перезаписується (поточна семантика `:592` зберігається).
- При читанні наявного `secrets.env` із правами group/other — одне stderr-попередження (без мовчазної зміни прав користувацького файла).
- Жодних значень секретів у stdout/stderr/тестових артефактах (тест із сідованим ключем).
- `load_secrets`-інʼєкція в `os.environ` (`:286-296`) — **не змінюється** (замінить SecretStore пізніше).
